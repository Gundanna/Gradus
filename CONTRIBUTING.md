# Contributing to Gradus

First of all, thank you for your interest in contributing to Gradus.

Gradus is built around innovation, collaboration, and the belief that great technology should be accessible to developers everywhere. We welcome developers, researchers, designers, and enthusiasts who want to help improve the project.

This document explains how to contribute.

## 1. Ways to Contribute

There are several ways to contribute to Gradus:

- **Code Contributions:** Improve existing functionality, fix bugs, and implement new features.
- **Bug Reports:** Identify and report unexpected behavior or technical issues.
- **Feature Requests:** Suggest improvements and new capabilities.
- **Documentation:** Improve guides, documentation, examples, and explanations.
- **Performance:** Optimize existing implementations and improve efficiency.
- **Security:** Responsibly report vulnerabilities and potential security issues.

Contributions of all sizes are welcome.

## 2. Getting Started

Before submitting a contribution:

1. Read the project's README.
2. Review the existing source code and project structure.
3. Check existing issues and pull requests to avoid duplicate work.
4. Understand the project's architecture and coding conventions.
5. Ensure your development environment is configured correctly.

## 3. Submitting Changes

We recommend the following workflow:

1. Fork the repository.
2. Create a separate branch for your changes.
3. Implement your modifications.
4. Test your changes thoroughly.
5. Commit your work with a clear and descriptive message.
6. Open a Pull Request describing your contribution.

Pull Requests should include:

- A clear description of the changes.
- The reason for the proposed modification.
- Relevant screenshots or examples when applicable.
- Testing information.
- Any relevant issue references.

Keep contributions focused and avoid combining unrelated changes into a single Pull Request.

## 4. Code Standards

Contributors are expected to:

- Write readable, maintainable, and well-structured code.
- Follow the project's existing coding conventions.
- Avoid unnecessary dependencies.
- Include appropriate comments where helpful.
- Test new functionality before submitting changes.
- Avoid introducing breaking changes without documenting them.

## 5. Reporting Issues

When reporting a bug, please include:

- A descriptive issue title.
- Steps to reproduce the problem.
- Expected behavior.
- Actual behavior.
- Relevant error messages or logs.
- Your operating system and environment, when relevant.

Feature requests should explain the problem they solve and the expected benefits.

## 6. Contribution Rights and Licensing

All contributions are subject to the project's applicable license.

By submitting a contribution, you acknowledge and agree that:

- You have the legal right to submit the contribution.
- Your contribution does not knowingly violate another party's intellectual property rights.
- Your contribution will be distributed under the project's existing license.
- You grant the project maintainers the rights necessary to use, modify, reproduce, distribute, and incorporate your contribution into the project under its applicable licensing terms.

You retain ownership of your original contributions unless otherwise agreed.

Contributors must not introduce code, assets, or dependencies that impose licensing obligations incompatible with the project's license.

## 7. Commercial Use and Distribution

Gradus permits developers to build, commercialize, and distribute independent products using the project, subject to its license.

However, the original software and modified versions retaining its identity as the original application cannot be commercially distributed as standalone products.

Contributing to Gradus does not grant additional commercial distribution rights beyond those provided by the project's license.

Refer to `LICENSE` for the complete terms and restrictions.

## 8. Community Standards

All contributors are expected to:

- Be respectful and constructive.
- Welcome different perspectives.
- Provide useful and actionable feedback.
- Avoid harassment, discrimination, or personal attacks.
- Focus discussions on improving the project.

We want Gradus to be a productive and welcoming environment for everyone.

## 9. Final Note

Gradus is a community-driven project, and every meaningful contribution helps move it forward.

Whether you're fixing a small bug, proposing a major feature, improving documentation, or helping other developers, we appreciate your involvement.

**Build something meaningful. Push technology forward.**

Thank you for contributing to Gradus.
